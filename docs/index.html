Why Nitrous

OEM control centers ask a lot.
Nitrous asks for one folder.

A typical vendor stack installs services, schedules updaters and wakes your discrete GPU just to read a temperature. Nitrous replaces the whole thing with a single executable you can move or delete.

The usual stack

Vendor control center

  • Background service and telemetry daemon
  • Wakes the dGPU to poll a sensor
  • Installer, drivers and updater bundled in
  • Settings applied with no baseline to return to
Nitrous

One portable executable

  • Nothing runs at idle except a quiet tray process
  • Sleeping GPUs are checked via Windows PnP, never woken
  • Single .exe, no installer, SHA-256 verified updates
  • Every change is clamped, isolated or backed up first

Capabilities

Everything you'd open NitroSense for.
Nothing you wouldn't.

Powered by the same Acer WMI classes and embedded-controller HID interface the OEM software uses. Nitrous probes what your model exposes at startup and enables only that.

Cooling

Cooling that thinks in curves.

Per-profile custom fan curves, manual control from 1% to 100%, Auto and Max. Ramp shaping spins fans up instantly under load but steps them down gradually, so short CPU bursts never turn into revving.

Power & EC

Firmware modes, not pretend buttons.

Quiet, Balanced, Performance and Turbo go straight to the firmware - through the embedded controller where there is one, through Acer WMI where there isn't - so the enforced GPU power limit follows. On an AN16S-61 that's 80 / 85 / 100 / 115 W; on a WMI-only ANV15-41, 65 W at Performance.

Display

Refresh rate that follows power.

Switch to any rate your panel advertises. Auto uses your chosen rate on AC and 60 Hz on battery. LCD overdrive appears only where the display reports support.

TOTAL LIGHTNING CONTROL

Four zones, and the lid.

Global and Area are two presets on one page: four per-zone colours or one effect across all zones, brightness and speed, plus the lid's cover logo with its own Static, Breathing and Neon effects. Follow the screen's colours, drive the active effect from the system audio with Peak, Spectrum, Beat or Vibe, or combine screen colours with an audio beat; saturation and a silence floor keep it controllable. The keyboard acknowledges a power-mode change in the mode's colour, and auto-off lives next to the hotkeys in Setup.

Safety by design

Every write has an undo.

Nitrous touches the embedded controller and the GPU driver. That's why each change is clamped, isolated or snapshotted before a single byte is written.

Nitrous is unofficial and not affiliated with Acer. Firmware varies between models — use it at your own risk.

  1. 01

    A hard 1% fan floor

    Manual speeds and custom curves are clamped in both the UI and the WMI layer, so a stale registry value can never zero-out your fans.

  2. 02

    CPU limits are backed up

    Original AC/DC min/max processor states are captured before modification and restored on exit or after an abrupt crash.

    HKCU\Software\Nitrous\CpuPowerBackup_<scheme>_{AC|DC}_{Min|Max}
  3. 03

    Boost mode is reversible

    Boost is a persistent Windows preference, so Nitrous keeps a snapshot and exposes an explicit RESTORE in Setup — even across reboots.

    HKCU\Software\Nitrous\CpuBoostBackup_<scheme>_{AC|DC}
  4. 04

    OEM services are snapshotted

    Before stopping anything, Nitrous records the exact start types, delayed-auto flags and running states. Services you had already disabled are left untouched.

    %LOCALAPPDATA%\Nitrous\acer-services-backup.json
  5. 05

    GPU clock ownership is opt-in

    Off by default, including across updates. With the switch off, startup, profile switches, hotkeys, AC/DC transitions, resume, the watchdog, APPLY and RESET perform zero GPU writes.

Compatibility

Probed, not hardcoded.

Nothing in Nitrous is pinned to a model string. At startup it inspects your SMBIOS tables, available WMI methods and EC HID interfaces, then enables what your firmware actually answers.

Quick start

Portable by default.

Download, verify, run. No installer and no service to uninstall.

1

Check the requirements

  • Windows 10 or 11, x64
  • .NET 10 Desktop Runtime (x64) required
  • Administrator — requested by the app manifest
  • An Acer Nitro laptop with the gaming WMI interface
2

Download and verify

Grab Nitrous.exe and SHA256SUMS from the latest release, then check the hash in PowerShell:

PowerShell 
Get-FileHash .\Nitrous.exe -Algorithm SHA256

Compare the output to the matching line in SHA256SUMS. Updates from inside the app are verified the same way.

3

Run it from anywhere

Move the .exe to a permanent folder and launch it. Nitrous lives in the tray — click the icon or press Ctrl + Home to summon the dashboard. Hotkeys are rebindable on the Setup page.

Disabling Acer services is strictly opt-in. If you do, Setup → Acer Background Services → RESTORE brings back the exact previous state.

Troubleshooting

If something looks off.

Most surprises come from another tool managing the same hardware, or from firmware that only implements part of the Acer protocol.

GPU offsets keep resetting to 0
  • Make sure the background tray process is running — the clock watchdog lives there.
  • Confirm Nitrous manages GPU clocks is ON in the GPU page.
  • Check %LOCALAPPDATA%\Nitrous\logs\nitrous.log for GPU OC, NVAPI or NVML warnings. Every write logs its trigger, old value and new value.
  • A dGPU in D3 sleep cannot be read or written. Nitrous checks the Windows PnP state without waking it and skips polling until the GPU wakes.
My Afterburner sliders or voltage curve reset

Run only one clock manager at a time. Either turn Nitrous manages GPU clocks OFF, or zero Afterburner's core and memory sliders and let Nitrous own per-profile offsets.

Nitrous writes a sparse P0 packet with 0 base-voltage entries, which replaces the driver's active P0 override and drops external voltage/frequency curves.

Fans aren't following my custom curve
  • Custom curves only execute when the fan mode is set to Custom / Medium and curve mode is on.
  • Confirm Nitrous is running as Administrator and your laptop exposes AcerGamingFunction.
  • If a WMI write fails, the engine retries on the next 2-second tick — the log shows the failure.
Acer hotkeys or lighting stopped working

Open Setup → Acer Background Services → RESTORE to re-enable and restart the OEM services.

If it reports already disabled; no Nitrous backup to restore, the services were disabled outside Nitrous — re-enable them in services.msc. A partial restore keeps acer-services-backup.json so you can retry.

A control is greyed out

Nitrous disables what your firmware doesn't answer instead of failing silently. Hover the control to see the exact reason.

  • Keyboard zones need a 4-zone RGB keyboard; single-colour models get one Colour chip instead.
  • The LIGHT tab is absent on models with no reachable lighting controller. The Fn keys may still work, but no user-mode interface exposes that.
  • The cover logo is confirmed once with a test colour; if it didn't light up, the controls are replaced by an explanation and nothing more is written.
  • Keyboard auto-off now lives in Setup → KEYBOARD and still uses a firmware timeout command, so it needs the embedded-controller interface.
  • USB charging while off needs an Acer WMI class that some BIOS versions implement only partially.
  • LCD overdrive is a panel property, so it is hidden rather than greyed where unsupported.
Auto-update says "manual download required"

The release didn't publish a GitHub asset digest or checksum file, so Nitrous refuses to update itself. Download it from the Releases page and verify the hash manually.

Where are my logs and diagnostic bundles?
  • %LOCALAPPDATA%\Nitrous\logs\nitrous.log — rotated at 1 MB, up to 3 archives, tagged by process role and PID.
  • %LOCALAPPDATA%\Nitrous\diagnostics — exported ZIP bundles.
  • HKCU\Software\Nitrous — preferences plus CPU power and boost baselines.

Export a bundle from Setup → Diagnostics → Export Diagnostics. Nothing is uploaded automatically: usernames, paths, SIDs, emails and IP/MAC addresses are scrubbed, and serial numbers and system UUIDs are never collected.

Found a bug or unsupported control?

Attach a redacted diagnostic bundle — it makes firmware differences actionable.
